# Nodra V0.1

Nodra V0.1 is a defensive laboratory and runtime baseline for containing autonomous AI-agent incidents.

## Security objective

Prove that one compromised agent can be prevented from contaminating an entire agent organization while preserving evidence needed to investigate and recover.

## Reference scenario

The owned five-agent laboratory contains Manager, Research, Finance, Support and Data. The test incident originates in Research, propagates through Manager to Finance and Data, while Support remains outside the affected branch.

## Runtime path

Agent request → Nodra runtime gateway → containment-state check → policy evaluation → optional approval → validated tool adapter → post-execution observation.

Denied requests never invoke the protected tool. Quarantined agents are blocked. Restricted or at-risk agents are limited by the V0.1 containment policy.

## Evidence and provenance

Security events are appended through the database recorder with workspace sequence numbers, previous hashes and SHA-256 event hashes. This is tamper-evident evidence, not an immutable ledger and not a record of hidden model chain-of-thought.

Causal edges connect observable agent actions. Incident investigation is scoped by the persisted incident identifier.

## Containment and recovery

The laboratory containment flow quarantines the origin and restricts affected descendants while preserving unaffected agents. Recovery requires remediation evidence for the required system checks plus explicit owner/admin human approval before safe restart can be assessed.

Laboratory reset preserves historical security events and resolves active laboratory incidents instead of deleting event-chain members.

## Trust boundaries

Supabase RLS isolates workspace data. Privileged remediation state changes use one atomic SECURITY DEFINER entry point with internal membership/role checks. Direct authenticated writes to remediation evidence and security events are denied where the trusted recorder/remediation path is required.

## V0.1 limitations

- The five-agent environment is a controlled defensive simulation.
- Runtime containment policy is intentionally simple and will need richer production policy semantics.
- Tool cancellation is cooperative: adapters must honor AbortSignal.
- Gemini execution requires a valid server-side key and live verification.
- Protected Gemini execution still requires a successful live model call through the guarded runtime path.
- Final desktop, tablet and mobile visual verification remains required before release.

## Security assurance references

Nodra V0.1 hardening is evaluated against public, vendor-neutral engineering guidance rather than treating feature completion as proof of security:

- NIST AI RMF and the Generative AI Profile: lifecycle risk identification, measurement, management, and governance.
- OWASP Top 10 for Agentic Applications 2026 and the Securing Agentic Applications Guide: goal hijacking, tool misuse, identity/privilege abuse, agentic supply-chain risk, unexpected code execution, and agent-specific red-team coverage.
- NASA-STD-8739.8B Software Assurance and Software Safety: systematic assurance, objective verification evidence, independent verification/validation principles, and lifecycle traceability.

These references are design and verification inputs only. They do not imply certification, approval, participation, or endorsement by NIST, OWASP, NASA, or any vendor.

## V0.1 assurance invariants

The release candidate must preserve these invariants under nominal and adversarial tests:

1. **Fail closed:** an unknown, paused, offline, or unresolved agent state cannot execute a protected tool.
2. **Least authority:** an agent can invoke only explicitly granted resource/action pairs; model output cannot expand authority.
3. **Containment before execution:** quarantine/restriction state is evaluated before a protected adapter runs.
4. **Authenticated provenance:** protected actions are attributable to workspace and agent identity and recorded through the signed gateway path.
5. **Replay resistance:** signed gateway requests cannot be reused after nonce consumption or accepted outside their validity window.
6. **Workspace isolation:** identities cannot read or mutate another workspace's protected security state.
7. **Evidence integrity:** event-chain verification detects tampering and incident evidence cannot be silently rewritten by ordinary authenticated clients.
8. **Selective blast radius:** containment isolates the affected branch without unnecessarily disabling unaffected agents.
9. **Recovery requires evidence:** restart is denied until required remediation checks have evidence and explicit authorized human approval.
10. **Model distrust:** Gemini/OpenAI output is treated as untrusted input, parsed into a constrained action schema, and passed through Nodra policy before tool execution.
11. **Credential confinement:** provider and gateway secrets remain server-side and are never returned in user-facing errors or evidence payloads.
12. **Release evidence:** V0.1 is not declared verified until automated, database, live protected-model, lifecycle, and responsive-layout checks have recorded evidence.
